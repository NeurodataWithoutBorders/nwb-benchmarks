## Summary

**What is well built.**

- The two pieces that define the shared data, the environment capture and the results reducer, are specified
  and tested with care. `setup/_environment.py:154-185` separates the raw capture from the content that is
  hashed, and `tests/test_environment.py:147-166` proves the ID ignores paths, ordering and warnings while
  reacting to a version change; five ways for `conda list` to fail are covered (`:108-126`).
  `setup/_reduce_results.py:67-74` says why NaN results and `null` samples are dropped, and
  `tests/test_reduce_results.py:10-16` pins that against a fixture written by the pinned asv version.
- Decisions are written down where they are made: `core/_base_benchmark.py:4-29` (why `number = 1` and no
  warm-up), `benchmarks/params.py:4-10` (which URLs are literals and why),
  `database/_processing.py:24-28,51-127` (every excluded sample with its numbers and a link),
  `.github/workflows/testing.yml:77-82` (how the smoke test picks one parameter set).
- The data format has guard rails: `AGENTS.md` states when each of three version numbers moves, and two
  workflows check it (`version_check.yml`, `format_version_check.yml`); `scripts/check_dandi_urls.py` keeps
  the hard-coded URLs honest in CI.
- The unit tests run offline by design (`tests/conftest.py:3-7`): 72 tests in under four seconds, no repeated
  test code in the duplication scan, and a seeded check that `--random` is deterministic
  (`tests/test_random_benchmark.py:19-25`).
- The layout follows the convention the project states (`docs/development.rst:29`): private `_module.py` files
  with re-exports in each `__init__.py`, in all five subpackages. `database/` imports nothing from the rest of
  the package.
- The lint baseline is clean (all seven pre-commit hooks pass) and pre-commit.ci keeps the hook pins current.

**Dominant themes.**

1. *The suite is written out per timing/network twin and per modality.* 1,056 of 7,111 code lines (14.9%) sit
   in repeated blocks, nearly all in four benchmark modules, and adding a streaming method takes about 33
   edits that nothing checks ([ARC-2](#arc-2), [ARC-3](#arc-3), [DUP-1](#dup-1), [DUP-2](#dup-2),
   [DUP-3](#dup-3), [DUP-4](#dup-4)). Three of the proposals were tried on scratch copies: together they
   remove about 530 lines, and the two snapshots of the appendix show the same 118 benchmarks, 882 parameter
   sets and `teardown` behavior before and after (apart from one combination that no run produces).
2. *Leftovers from earlier states.* Unused imports, settings that change nothing, a template's `conf.py`, and
   documentation of a file format and commands that no longer exist ([DC-1](#dc-1) to [DC-4](#dc-4),
   [CL-5](#cl-5)).
3. *Stated rules that the code follows in part.* Return annotations (43% of functions have one), NumPy
   docstrings (three styles in use), and the "little inheritance" philosophy ([CL-1](#cl-1), [CL-2](#cl-2),
   [CL-3](#cl-3), [NV-15](#nv-15)).
4. *One class is a third of the package.* `BenchmarkVisualizer` has 2,641 lines and 66 methods and almost no
   tests ([ARC-4](#arc-4), [CON-1](#con-1), [DUP-6](#dup-6)).
5. *Import-time coupling.* An import cycle that works in one order only, and a package `__init__` that loads
   and does everything ([ARC-1](#arc-1), [NV-6](#nv-6)).

**Needs a maintainer's eye soon.** Running the project's own figure command during this review stopped twice
on a fresh setup: a cache directory that is never created when `--results-dir` is given, and SciPy missing from
every dependency group ([NV-1](#nv-1)). A failed packet capture is recorded as a successful sample of zeros,
which has already reached the results once ([NV-2](#nv-2)). The supported Python range includes a version that
reached end-of-life on 2026-10-01 and excludes the newest release ([NV-8](#nv-8)); the three GitHub Actions
majors in use predate the runner's current Node runtime ([NV-9](#nv-9)); and the documentation build pins a
Jinja2 line with five published advisories ([NV-10](#nv-10)).

1 security-sensitive finding withheld; reported to the requester in the review session.

**House recommendations** (`HOUSE_PREFERENCES: guides`; not findings). The Python guide recommends pixi for
environments, locks and tools. Here it would replace `environments/nwb_benchmarks.yaml` and its pip block with
one manifest and a lock file, and the `setup-miniconda` and cache steps of `testing.yml:31-56` with a pixi
setup step. The project's own instruction stands until it decides otherwise: `docs/setup.rst:15` tells users to
run `conda env create --file environments/nwb_benchmarks.yaml`, and `asv.conf.json:11-12` names that file.

## Findings

### Architecture

#### ARC-1 — `globals` and `setup` import each other, so the package imports in one order only <a id="arc-1"></a>

- **Location**: `src/nwb_benchmarks/globals.py:3`, `src/nwb_benchmarks/setup/_configure_machine.py:17-18`,
  `src/nwb_benchmarks/setup/_reduce_results.py:15`, `src/nwb_benchmarks/core/_clean_results.py:7-10`,
  `src/nwb_benchmarks/core/_streaming.py:23`
- **Issue**: `globals.py` imports `get_benchmarks_home_directory` from `setup`, and two `setup` modules import
  constants from `globals`. `ruff analyze graph` shows the cycle `globals.py` → `setup/__init__.py` →
  `setup/_configure_machine.py`, `setup/_reduce_results.py` → `globals.py`. It works because `setup` always
  happens to be imported first, and the code says so:

  ```python
  # core/_clean_results.py:7-10
  # Imported here rather than at module level: `globals` imports `setup`, and `setup` imports
  # `globals` while collecting machine info, so `globals` must never be the first of the two to
  # be imported. Importing `setup` above guarantees the order.
  from ..globals import ENVIRONMENTS_DIR, LOGS_DIR, MACHINES_DIR, RESULTS_DIR
  ```

  OBSERVED: swapping lines 13 and 14 of `command_line_interface.py` (`from .core …` and `from .globals …`) in
  a scratch copy makes `import nwb_benchmarks` fail with `ImportError: cannot import name
  'MACHINE_FILE_VERSION' from partially initialized module 'nwb_benchmarks.globals'`. isort keeps the working
  order only because "core" sorts before "globals". Two smaller self-imports have the same shape:
  `_configure_machine.py:18` (`from ..setup import read_config`, from the package that is importing it) and
  `_streaming.py:23` (`from . import download_asset_if_not_exists`).
- **Proposed change**: make `globals.py` a leaf. Compute `HOME_DIR = pathlib.Path.home() / ".nwb_benchmarks"`
  there (its `import pathlib`, unused today, then has a use) and let
  `setup/_config.py:get_benchmarks_home_directory` do `HOME_DIR.mkdir(exist_ok=True)` and return `HOME_DIR`,
  imported with `from ..globals import HOME_DIR`, so the directory name stays defined once. Then
  `_clean_results.py` imports its four directories at module level and the comment goes;
  `_configure_machine.py` uses `from ._config import read_config`; `_streaming.py` uses
  `from ._dandi import download_asset_if_not_exists`. Keep `from ..globals import …` as the import form in
  `_reduce_results.py`: `tests/test_reduce_results.py:40-43` patches `RESULTS_DIR`, `ENVIRONMENTS_DIR` and
  `MACHINES_DIR` as attributes of that module.
- **Confidence it's safe**: **High**. Trace: `git grep -nE
  "MACHINE_FILE_VERSION|DATABASE_VERSION|HOME_DIR|RESULTS_DIR|ENVIRONMENTS_DIR|MACHINES_DIR|LOGS_DIR|get_benchmarks_home_directory"
  -- src tests` finds five importing modules, all of the form `from .globals import` or `from ..globals
  import`; `HOME_DIR` is used only inside `globals.py`; the function has three callers (`globals.py:8`,
  `_config.py:28`, `_clean_results.py:13`). The two version-check workflows read `globals.py` with `sed` for
  lines that do not change. One difference remains: `Path.home()` is evaluated once at import instead of on
  every call; nothing in `src` or `tests` changes the home directory after import (`git grep -nE
  "Path\.home|\"HOME\"|expanduser" -- tests` finds nothing).
- **Verification**: `python -m pytest tests` (72 passed before); then repeat the experiment above: with lines
  13 and 14 of `command_line_interface.py` swapped, `python -c "import nwb_benchmarks"` must succeed.

#### ARC-2 — One more streaming method means about 33 edits in 7 files, and nothing checks the timing/network mirror <a id="arc-2"></a>

- **Location**: `src/nwb_benchmarks/core/_streaming.py:33-167`, `src/nwb_benchmarks/core/__init__.py:11-35,37-71`,
  `src/nwb_benchmarks/benchmarks/time_remote_file_reading.py`,
  `src/nwb_benchmarks/benchmarks/network_tracking_remote_file_reading.py`,
  `src/nwb_benchmarks/benchmarks/time_remote_slicing.py`,
  `src/nwb_benchmarks/benchmarks/network_tracking_remote_slicing.py`,
  `src/nwb_benchmarks/database/_visualization.py:22-49,551-559`
- **Issue**: the change the suite is built for is "one more way to read a remote file". Counting the places
  for one HDF5 backend with and without cache: four reader functions in `_streaming.py` (4); the import list
  and `__all__` of `core/__init__.py` (2); in each of the two file-reading modules one import block, four
  methods and two "preloaded" classes (14); in each of the two slicing modules one import block and four
  classes (10); `DEFAULT_BENCHMARK_LABELS`, `DEFAULT_METHOD_COLORS` and a branch in
  `_cache_stack_from_benchmark_name` (3). That is 33 edits in 7 files. No test, type check or CI step fails

  filter to the configured order (`_visualization.py:1501-1505,1569-1573`), and the mirror between timing and

  tracker" (`network_tracking_remote_file_reading.py:4-5`), "all of the benchmarking classes should be the
  same" (`network_tracking_remote_slicing.py:4-5`). OBSERVED today the mirror holds: 29 = 29 file-reading
  benchmarks once the `time_read_` and `track_network_read_` prefixes are stripped, and 20 = 20 slicing
  classes with identical parameters.
- **Proposed change**: add a unit test that states the rule: the class names of `time_remote_slicing` and
  `network_tracking_remote_slicing` are equal and each pair has the same `params`; the `(class, operation)`
  pairs of the two file-reading modules are equal after stripping the prefixes. Compare the module contents
  with `inspect`, not the discovered suite, so the result does not depend on whether tshark is configured.
  [DUP-1](#dup-1) then removes the second copy of the slicing setups and [CON-1](#con-1) merges the label and
  color tables, which brings the count to about 20.
- **Confidence it's safe**: **High**. It adds a test and changes no shipped code; the comparison it encodes
  passes on the current tree (figures above, from the suite snapshot in Appendix A).
- **Verification**: `python -m pytest tests` gains the test and it passes; deleting one class from
  `network_tracking_remote_slicing.py` must make it fail.

#### ARC-3 — The three modalities are spelled out in 15 places in two packages <a id="arc-3"></a>

- **Location**: `src/nwb_benchmarks/database/_visualization.py:90,546,871,1014,1201,1202,1300,1432,2403`,
  `src/nwb_benchmarks/database/_processing.py:251`, `src/nwb_benchmarks/benchmarks/params.py:220,225,264,271,278`
- **Issue**: `MODALITY_ORDER = ["Ecephys", "Ophys", "Icephys"]` exists (`_visualization.py:90`) and is read
  twice (`:2035,2256`), while eight other places in the same module spell the set again: local
  `modality_order` lists at `:546,871,1014,1201,1300` (two of them with `"all"` or `"unknown"` added), inline
  lists at `:1432,2403`, and a marker dict at `:1202`. `_processing.py:251` has the set as a regular expression
  (`r"^(Ophys|Ecephys|Icephys)"`), and `params.py` has it as a set (`:220`), as prose in an error message
  (`:225`) and as three `modality=` values. A fourth modality needs every one of them, and nothing checks the
  regular expression or the lists: rows of an unlisted modality get `modality = null` and drop out of every
  panel without a message.
- **Proposed change**: inside `database/`, define `MODALITY_ORDER` once in `_processing.py` (from which
  `_visualization.py` already imports), build the pattern from it (`rf"^({'|'.join(MODALITY_ORDER)})"`; no
  alternative is a prefix of another, so their order does not change a match), and replace the seven
  lists with `MODALITY_ORDER`, `["all", *MODALITY_ORDER]` and `["all", *MODALITY_ORDER, "unknown"]`.
  In `params.py`, derive `valid_modalities` and the message from the modality table of [DUP-2](#dup-2). The
  lower-case names of the suite and the capitalized names parsed from old result files stay two definitions:
  `database/` reads results of any age and should not follow the suite's current list.
- **Confidence it's safe**: **Medium**. Every replaced literal has the same elements in the same order as
  the constant (search: `git grep -nE '"Ecephys", "Ophys", "Icephys"|Ophys\|Ecephys' -- src`), and no place
  modifies its list (`git grep -nE "modality_order\.(append|remove|insert|sort|pop|extend)" -- src` finds
  nothing). The rating is not higher because four of the lists (`_visualization.py:871,1014,1201,1300`) only
  order figure panels, palettes and legends, which nothing checks.
- **Verification**: `python -m pytest tests` and the suite snapshot of Appendix A for `params.py`; the
  figure-run manifest of Appendix C for the regular expression and the lists that reach a table
  (`_visualization.py:546,1432,2403`). For the four figure-only lists: no project command reveals this.

- **Confidence it's safe**: **Medium**. The trace is by reading (`self.` inside `:439-665` and `:683-777`

- **Verification**: the figure-run manifest of Appendix C: the `network_runtime_*`, `cache_effect_*` and

### A. Suite snapshot

Describes what ASV discovers: for each of the 118 benchmarks its name, parameter sets, timing attributes and
a digest of the source of its benchmark function and `setup`; and the `repr` of the 32 parameter tables. Save
as `snapshot_suite.py`, run from the repository root, and compare the files written before and after a change.

- Unchanged code: `benchmarks: 118; parameter tables: 32; sha256:
  5054acb4da845dd1a556f566325f86a568bf369f17d8a7f34464e5c82b4fe317`, identical in two runs.
- It changes when a class is renamed, when one slice list loses an entry, and when one `setup` body is
  edited (three separate breaks, three different digests).

```python
"""Write a stable description of the benchmark suite as ASV discovers it, and of the parameter tables.

Usage, from the repository root with the package installed:  python snapshot_suite.py before.json
It needs no network: the DANDI lookup made when `params` is imported is replaced, as tests/conftest.py does.
Every opt-in family is switched on so that no benchmark is left out. The snapshot goes to a file because
importing `nwb_benchmarks` prints to standard output.
"""
import hashlib
import inspect
import json
import os
import pathlib
import sys
import textwrap

os.environ["RUN_DOWNLOAD_BENCHMARKS"] = "1"
os.environ["RUN_INCREMENTAL_SLICING_BENCHMARKS"] = "all"
os.environ["TSHARK_PATH"] = "tshark"  # any non-empty value keeps the network benchmarks listed

import nwb_benchmarks.core  # noqa: E402

nwb_benchmarks.core.get_https_url = lambda dandiset_id, dandi_path, follow_redirects=1: (
    f"https://example.invalid/{dandiset_id}/{dandi_path}"
)

from nwb_benchmarks.benchmarks import params  # noqa: E402
from nwb_benchmarks.setup import discover_benchmarks  # noqa: E402


def source_digest(function) -> str:
    """Digest of a function's source text, so that a moved but unchanged `setup` or benchmark body compares equal."""
    source = textwrap.dedent(inspect.getsource(inspect.unwrap(function)))
    return hashlib.sha256(source.encode()).hexdigest()[:16]


suite = {}
for benchmark in discover_benchmarks():
    owner = benchmark.func.__self__  # the benchmark class instance that ASV created
    suite[benchmark.name] = dict(
        type=type(benchmark).__name__,
        params=benchmark.params,
        param_names=benchmark.param_names,
        timeout=benchmark.timeout,
        **{key: getattr(benchmark, key, None) for key in ("number", "repeat", "rounds", "warmup_time", "unit")},
        benchmark_source=source_digest(benchmark.func),
        setup_source=source_digest(owner.setup) if hasattr(owner, "setup") else None,
        teardown_defined=hasattr(owner, "teardown"),
    )
tables = {
    name: f"{type(value).__name__}:{value!r}"
    for name, value in sorted(vars(params).items())
    if not name.startswith("_")
    and not callable(value)
    and (name.endswith(("_params", "_slices")) or name.startswith("RUN_"))
}
text = json.dumps(dict(benchmarks=suite, params=tables), indent=1, sort_keys=True, default=repr)
pathlib.Path(sys.argv[1]).write_text(text)
print(f"benchmarks: {len(suite)}; parameter tables: {len(tables)}; sha256: {hashlib.sha256(text.encode()).hexdigest()}")
```

### B. Teardown snapshot

Records what each benchmark class's `teardown` closes, and in which order, for every combination of the
resources its methods can set. Save as `snapshot_teardown.py` and use it like the first.

- Unchanged code: `benchmark classes: 83; sha256:
  66183c001d644eb8679ce6801060d154cfa440a5aa4725e56785de3e03edcae0` (602 combinations), identical in two runs.
- It changes when two `close` calls of one `teardown` are swapped.

```python
"""Record what every benchmark class's `teardown` closes, and in which order.

Usage, from the repository root with the package installed:  python snapshot_teardown.py before.json
For each concrete benchmark class, every combination of the resource attributes that its methods assign is tried. No file is opened and no network is used: the resources are stand-ins that log the calls made
on them.
"""
import ast
import hashlib
import importlib
import inspect
import itertools
import json
import pathlib
import pkgutil
import shutil
import sys
import textwrap

import nwb_benchmarks.core

nwb_benchmarks.core.get_https_url = lambda dandiset_id, dandi_path, follow_redirects=1: (
    f"https://example.invalid/{dandiset_id}/{dandi_path}"
)

import nwb_benchmarks.benchmarks  # noqa: E402

RESOURCES = ("io", "file", "bytestream", "client", "tmpdir")
calls = []


class Resource:
    def __init__(self, label: str):
        self.label = label
        self.name = f"<{label}.name>"

    def close(self) -> None:
        calls.append(f"{self.label}.close")

    def cleanup(self) -> None:
        calls.append(f"{self.label}.cleanup")


def assigned_resources(cls: type) -> tuple:
    """The resource attributes that any method of `cls`, inherited or assigned from elsewhere, sets on `self`."""
    assigned = set()
    for _, function in inspect.getmembers(cls, inspect.isfunction):
        tree = ast.parse(textwrap.dedent(inspect.getsource(inspect.unwrap(function))))
        for node in ast.walk(tree):
            if isinstance(node, ast.Attribute) and isinstance(node.ctx, ast.Store) and node.attr in RESOURCES:
                assigned.add(node.attr)
    return tuple(label for label in RESOURCES if label in assigned)


shutil.rmtree = lambda path, ignore_errors=False: calls.append(f"rmtree({path}, ignore_errors={ignore_errors})")

snapshot = {}
for module_info in pkgutil.iter_modules(nwb_benchmarks.benchmarks.__path__):
    module = importlib.import_module(f"nwb_benchmarks.benchmarks.{module_info.name}")
    for class_name, cls in inspect.getmembers(module, inspect.isclass):
        if cls.__module__ != module.__name__ or inspect.isabstract(cls):
            continue
        reachable = assigned_resources(cls)
        per_class = {}
        for size in range(len(reachable) + 1):
            for present in itertools.combinations(reachable, size):
                instance = object.__new__(cls)
                instance.lindi_file = "<a path that does not exist>"
                for label in present:
                    setattr(instance, label, Resource(label))
                calls.clear()
                if hasattr(instance, "teardown"):
                    instance.teardown({})
                per_class["+".join(present) or "(none)"] = list(calls)
        snapshot[f"{module_info.name}.{class_name}"] = per_class

text = json.dumps(snapshot, indent=1, sort_keys=True)
pathlib.Path(sys.argv[1]).write_text(text)
print(f"benchmark classes: {len(snapshot)}; sha256: {hashlib.sha256(text.encode()).hexdigest()}")
```

### C. Figure-run manifest

Runs the project's own figure command on a fixed copy of the public results and lists a digest of every CSV
table it writes. With SciPy installed ([NV-1](#nv-1)) and `HOME` set to a directory that contains
`.cache/nwb-benchmarks`:

```bash
git clone https://github.com/NeurodataWithoutBorders/nwb-benchmarks-results
```

```bash
MPLBACKEND=Agg nwb_benchmarks generate_figures --results-dir nwb-benchmarks-results --output-dir figures --summary-tables-dir tables
```

```bash
(cd tables && find . -name '*.csv' -print0 | sort -z | xargs -0 sha256sum) > tables.sha256
```

Compare `tables.sha256` before and after a change with `diff`.

- Unchanged code, results repository at 3897a03, polars 1.44.2, pandas 3.1.1, numpy 2.5.5, SciPy 1.18.1: 192
  tables, and `sha256sum tables.sha256` gives
  `d2280a83f60e42ad235bb6d8999517bb9c3743d5163d1f0a7fd72fc5a1fc5e42`. Two runs gave the same list. One run
  takes 18 to 19 minutes here. The digests depend on the results commit and on the installed versions, so
  take the "before" list in the environment that will produce the "after" list.
- Deliberate break: with `median()` replaced by `mean()` in `_safe_median` (`database/_visualization.py:221`),
  3 of the 192 digests change: `cache_effect_summary.csv`, `cache_effect_method_summary.csv` and
  `preload_effect_summary.csv`, the three tables that function feeds. The other 189 do not depend on it: the
  manifest shows a change only in the tables the changed code reaches.

  code.

### D. `aws_region` with a file-like object

```python
import io

import h5py
import numpy as np

buffer = io.BytesIO()
with h5py.File(buffer, "w") as file:
    file["d"] = np.arange(4)
with_region = h5py.File(io.BytesIO(buffer.getvalue()), "r", aws_region=b"us-east-2")
without_region = h5py.File(io.BytesIO(buffer.getvalue()), "r")
assert with_region.driver == without_region.driver == "fileobj"
assert with_region.id.get_access_plist().get_driver() == without_region.id.get_access_plist().get_driver()
assert (with_region["d"][:] == without_region["d"][:]).all()
```

Passes with h5py 3.16.0.
